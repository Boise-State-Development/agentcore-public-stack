**The most consequential finding is a reversal of our own recommendation from last week.** The GPT-6 Astra model card's tier headings settle the blocking question we left open: *"short context (**272K input tokens or fewer**)"* / *"long context (**more than 272K input tokens**)"*. The price tier is selected by **actual input tokens on the request**, not by the declared context window. (b) Encode **all four** long-tier rates literally ($22.00 / $27.50 / $2.20 / **$82.50**), because output is 1.5×, not 2×, and a `× 2` helper would overstate it by 33%. (c) Take the **Mantle Responses** path, not Converse: per the card, prompt caching is listed only under `bedrock-mantle`/Responses, and `bedrock-runtime` Converse would re-pay the whole prefix at $11/MTok every turn. (d) Leave `cacheReadMultiplier` at the default — Astra is 0.100× in both tiers and is *not* a third counterexample.
- **Subtracts**: a queued recommendation that would have shipped a capability regression; the `long = short × 2` mental model; and the lingering ambiguity about which API surface to reach Astra through.
- **Unlocks**: a genuine **1M-token tier** — the first model in the catalog where a whole corpus fits in one turn — with no artificial cap; and a **tier-aware catalog**, so the admin page can show the boundary, cost projections can respect it, and Astra's 10× output-token quota burn can be accounted for against the known campus TPM ceiling. The 272K cap survives as an optional *policy* lever.
- **Effort × Impact**: **Low × High**
- **Verdict**: **Worth trying — recommended #1.** It is the cheapest item in the scan and the only one where acting on last week's doc would actively make things worse. ⚠️ Two constraints carry forward unresolved: the ref repo's `rejectsTemperature: true` is **still not on the model card** — verify, don't copy; and Astra's cache-write SKU is a **30-minute** TTL, which must not be folded into `cache_ttl_seconds_for()`'s 5m/1h assumptions. ⚠️ `bedrock-mantle` is us-west-2 only (matches us), and on `bedrock-runtime` Astra supports no server-side tool use, no structured output and no CountTokens.

### 2. Make the Strands 1.56.0 bump a paired pin — and enforce the two guard rails we currently only document

- **Unlocks**: the first-party Strands **context-manager / offloading stack is fully released in 1.56.0** (#4118/#4146/#4187/#4231/#4254/#4282, and `ContextOffloader` manual offloading closed as released) — it becomes pinnable and evaluable against ours, with #4367's `NAMESPACED` stash sentinel offering **cross-session offload sharing** for the document-offload work.

This idea makes it *evaluable*, not adopted.

### 3. Sweep the cacheable prefix for derived and relative values — and close the last daily boundary

- **Source**: Claude Code 2.1.275 (*"a restored memory file's age note changing between requests after a compaction or resume, which caused prompt cache misses"*) and 2.1.269/2.1.273 — https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md — plus our own `9f246cb7`.
- **Surface area**: `agents/main_agent/utils/` (`get_current_date_pacific()` and the `SystemPromptBuilder` tail), `session/turn_based_session_manager.py` (the truncation anchor), `session/document_rehydration.py`, `apis/shared/sessions/messages.py`, and the interrupt-resume path in `inference_api/chat/routes.py`.
- **Change**: (a) a **grep-plus-test sweep** for any *derived or relative* value that can reach the system prompt or restored history — relative timestamps, "N days ago", recomputed ages, sizes recomputed at read time. I checked the obvious paths and found none today; the point is to make that a test rather than an observation, because it is exactly the kind of thing a future feature adds without noticing. (b) Extend the sweep to the resume path specifically, where Claude Code found two of its four bugs. (c) Decide the remaining **daily** boundary: `9f246cb7` took the date line from 24 rewrites a day to 1, but a session open across Pacific midnight still re-pays the whole prefix once — either drop the date from the cacheable segment entirely, or place it after the last cachePoint.
- **Subtracts**: the final *scheduled* prefix rewrite, and an entire category of invalidation that currently has no detector even though we already own the instrument to detect it.
- **Effort × Impact**: **Low–Medium × Medium–High** — a grep, a test, and one placement decision.
- **Verdict**: **Worth trying.** The unusual thing here is that we are ahead of the ecosystem on *detection* (`systemPromptHash` / `toolConfigHash` / `historyHash` on every `C#` row, plus `partial_miss`) and behind on *sweeping*. ⚠️ Pair it with Claude Code's other finding — the context meter double-counting advisor-tool turns, which fired auto-compact at half the real window — by asserting our per-turn context size for tool-heavy turns tracks CountTokens. **Over-counting is a pure cost bug and it fails silently.** ⚠️ CountTokens rejects `us.*` ids, so that assertion needs a `global.*` id or an alternative estimator.

### 4. Fix the MCP Apps header's tool display name — `title` → `annotations.title` → `name`

- **Source**: https://github.com/modelcontextprotocol/ext-apps/pull/778 (opened 2026-09-18, fixing ext-apps issue #767) — **narrows the open `[2026-09-11] Retire the ClientSession monkeypatch via _meta serverInfo` entry**; this is an independent, shippable piece of the same header.
- **Surface area**: `backend/src/apis/shared/mcp_apps/ui_resource_store.py:215`, `card_store.py:160`, the `toolName` derivation feeding both the header-only shell at `content_block_start` and the full html-bearing `ui_resource` emit, and the App frame header component in the SPA.
- **Change**: derive the displayed tool name by the base MCP schema's precedence — `title`, then `annotations.title`, then `name` (for `Tool` specifically, `annotations.title` outranks `name`). Today we write the raw agent-facing `tool_name` straight through; **verified: `apis/shared/mcp_apps/` contains no `title` or `annotations` handling at all.**
- **Subtracts**: no — addition. Justified because the wrong string is **persisted with the resource**, so it survives reload: the App frame header shows `raw_tool_name` while the tool rail immediately beside it shows the friendly title, and the two disagree permanently.
- **Unlocks**: spec-conformant App headers, on the same precedence every other MCP host is converging to — and it is a prerequisite for the eventual `_meta serverInfo` migration rather than competing with it.

- **Verdict**: **Worth trying.** Small, self-contained, and confirmed against our tree rather than inferred. ⚠️ The upstream PR is **open, not merged**, so treat it as evidence of the correct precedence (which comes from the base schema, not the PR) rather than as a shipped standard. ⚠️ While in this file, note that `ext-apps` v2.0.0 changed host-facing error codes (`-32002` → `-32602`, `-32603` → `-32602`) and removed the `MCP error N:` message prefix — the App-error chain from #1009/#1013 was built substantially on message text and deserves a grep in the same PR.

### 5. Defer external MCP tool discovery to session scope — and add the sidebar conversation search while in the SPA

- **Source**: https://github.com/aws-samples/sample-strands-agent-with-agentcore/pull/294 (lazy loaders; measured "Starting" 10.417s → 4.081s, follow-up 7.377s → 1.117s) and https://github.com/aws-samples/sample-strands-agent-with-agentcore/pull/296 (sidebar search); corroborated by opencode #49276 (revision-keyed catalog reuse) and #49387 (skip warming for subagents).
- **Surface area**: `backend/src/agents/main_agent/base_agent.py:478` (`_build_filtered_tools`), `integrations/external_integration.py` and `gateway_integration.py`; and separately `frontend/ai.client/src/app/components/sidenav/components/session-list/session-list.{ts,html}`.
- **Change**: (a) stop loading every enabled external MCP client at agent build. Defer discovery for tools **not in this session's `enabled_tools`** — a set that is stable for the session — and leave the in-session set eager. (b) Confirm we make no equivalent keep-alive/warm-up call when an `@`-mention builds a second `Agent` (opencode #49387 found exactly that cost per subagent). (c) Independently, add a client-side "Search chat titles" filter to the session list: live result count, date grouping suppressed while filtering, "No matching chats" distinguished from "No conversations yet", Escape to clear, query preserved across refreshes — plus `inert` on the off-canvas panel while closed.
- **Subtracts**: the eager load of every enabled external MCP client at agent build, on every agent construction.
- **Unlocks**: their measured **60–85% first-token latency cut** on new and follow-up conversations; and a conversation-search affordance we have **none** of today — `session-list.ts` groups by date with no filter at all, and it costs **zero tokens** (a pure client-side filter over already-loaded titles).
- **Effort × Impact**: **Medium × Medium–High**
- **Verdict**: **Worth trying**, with one hard boundary. ⚠️ **Session-scoped only — never turn-scoped.** Their implementation goes further than this proposal: their new base prompt tells the model *"available tools may change between turns within the same conversation"*, accepting a `toolConfig` that varies per turn. For us that is a `toolConfigHash` rewrite at 1.25× base input over a 30k–150k-token prefix, every turn — the latency win would be paid for many times over in cache writes. ⚠️ Their registry fix (module global → per-agent, resolved off `tool_context.agent`) is the same bug class as our "never cache session state on an agent instance" rule; worth reading before touching this code. ⚠️ The two halves are independent — the SPA search can ship alone if the backend half needs more design.

## Take

The system is trending **toward** the ecosystem, and this week it is the ecosystem arriving at conclusions we had already written down: Skills over MCP went Final with a lazy-read, manifest-bound-approval design that restates our own cost tenet almost clause for clause; opencode shipped attachments-by-path, which is our document-offload epic with the `DOCUMENT_READ_ENABLED` coupling made structural instead of remembered; and Claude Code spent a week fixing prompt-cache invalidation bugs that are #741 and #751 under other names. The uncomfortable finding is that our own recommendation from last week was wrong — the Astra price tier is per-request, not per-declared-window, so the `maxInputTokens: 272000` cap queued as "ship" would have thrown away a 1M-token capability to solve a problem that does not exist. Fix that first; it is the cheapest item here and the only one where last week's doc is actively misleading. What Phil would notice first if shipped: GPT-6 Astra in the model picker with its real window, and — on the next cost-anatomy read — a `systemPromptHash` that finally holds steady across a midnight boundary.
