### Patterns worth considering

- **Bound one tool call's wall time to the cache window.** Claude Code backgrounds a long shell command at 3 minutes so the next model call still reads the cache. For us, a tool that runs past the 5-minute TTL inside a turn (a long `browse_web`, a `document_extract` batch, a slow MCP call) makes the next call in the same turn a full re-write. **Monitor**: first read how many `C#` rows show a miss *within* a turn after a long tool. The #1882 cost replay groups rows by session, so it can probably answer that cheaply.
- **Check a summary is a summary before it replaces history.** Claude Code's idle-compaction bug was a non-summary reply accepted as the summary. Our cut writes the summarizer's output in place of turns; a cheap shape check (non-empty, under a size bound, not an assistant-style answer) before persisting the checkpoint costs nothing on the turn path. **Monitor**; worth a test if #1882's idle job ships, since that's the same failure mode.
- **Error messages that steer the model** (opencode, Claude Code's schema-in-error). Pattern-only; our tool errors already stream as messages.

### 1. Drop `strands-agents-tools`
- **Source**: https://github.com/strands-agents/tools/releases/tag/v0.9.0; migration guide in harness-sdk `site/.../migrate/strands-agents-tools.mdx`.
- **Surface area**: `agents/main_agent/tools/tool_registry.py:93`, `apis/inference_api/warmup.py:59`, `backend/pyproject.toml:74` and `:164-173`, `uv.lock`, any Lambda requirements that pull it, `USAGE_EXAMPLES.md:173`.
- **Change**: add `agents/main_agent/tools/calculator.py` with the same tool name and input schema as `strands_tools.calculator`, so the `toolConfig` bytes are identical and the prompt cache is unaffected. Verify that with the golden-request fixture (`tests/fixtures/bedrock_golden_requests.json`). Then remove the dependency, the pillow override and the warm-up entry. Upstream suggests `vended_tools.shell` running `python3 -c`, but that is a shell tool and not an acceptable replacement.
- **Subtracts**: one deprecated dependency, the pillow override and its comment block, and a Dependabot bump that would break import.
- **Effort × Impact**: Low × Medium
- **Verdict**: Worth trying. ⚠️ Byte-identical spec is the whole point; if the vendored schema differs, it's a one-time `toolConfig` re-write for every live session, so price it or match it.

### 2. Nightly: delete the orphaned ALB log bucket

### 3. Spike AgentCore Web Answer

### 4. Single-iframe MCP Apps hosting
- **Source**: https://github.com/modelcontextprotocol/ext-apps/pull/717
- **Surface area**: the SPA's App frame component, `ui_resource.sandboxOrigin`, the mcp-sandbox CDK construct, the `CDK_MCP_SANDBOX_ENABLED` consumption in inference-api.
- **Change**: a design note, not code. Can the SPA frame an App in one sandboxed iframe (opaque origin, strict CSP, `srcdoc` or a first-party stream) and meet #717's criteria? If so, `sandboxOrigin` becomes optional, and the empty-origin "cannot frame" state disappears. Wait for the tagged release and `basic-host`'s single-iframe example before writing code.
- **Subtracts**: the mcp-sandbox stack as a hard requirement for Apps (it could stay as an option), and one iframe hop.
- **Unlocks**: MCP Apps working on any deployment, including forks that never deploy the sandbox stack.
- **Effort × Impact**: Medium × Medium
- **Verdict**: Monitor → design note once ext-apps tags a release.

## Take

The ecosystem is absorbing the layers we built on: Strands took its tools into the SDK, MCP Apps loosened its sandbox, and AWS is turning search and workflows into Gateway targets. **This week's best moves are subtractions that follow those upstream changes**, and the cheapest is dropping `strands-agents-tools` before Dependabot proposes 0.9.0. The change that matters most for Phil's week is the nightly: last week's fix moved the failure instead of ending it, and it has been red three more nights.
