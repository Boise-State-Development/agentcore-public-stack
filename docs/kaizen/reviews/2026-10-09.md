## Week in Review

A 116-PR, zero-revert week that shipped two product epics (conversation search end to end, Shared Projects memory governance) and two releases. The kaizen queue got the leftovers. Three signals stand out.

**We are hitting platform ceilings one per deploy.** IAM's 6,144-character policy limit failed a dev Platform deploy on 10-08 (`89fc103d`). The first V2 flip on 10-09 was rolled back on an **undocumented 2,560-byte environment cap** (3,007 B in dev, 49 of 50 variables). The stack is at 460 of 500 resources. Each ceiling has its own hand count.

**Upstream moved toward us on cost and away from us on history.** Claude Haiku 5.5 (10-07) is the natural successor to our default and says it is ~75% cheaper. It is also a preserved-thinking model, and Anthropic's docs now say client-side compaction that keeps recent turns, which is ours, gets a 400. **Prod found a failure the research had marked latent.** Duplicate MCP tool names (`whoami` on two servers; one server registered under two catalog records) take down the whole agent. Schedules hit it far more than chat because a schedule snapshots every tool the role allows.

## Proposals — ranked

### 1. MCP tool registration never fails the agent: dedupe servers by URL, skip duplicate names, honour the cursor, cap name length
- **Source**: issue #1527 (prod, 10-09); research/2026-10-09.md ▸ Top 5 #5; review-queue.md ▸ [2026-10-09] Gateway pagination entry.
- **Surface area**: backend. `agents/main_agent/integrations/external_mcp_client.py`, `gateway_mcp_client.py:136-160`, `mcp_apps.py` (`UICapableMCPClient`), and wherever the agent's tool list is assembled.
- **Change**:
  - Dedupe MCP clients by server URL before building, so two catalog records for one server (the `google_tasks_employee` / `_student` case) load it once.
  - On a duplicate tool name, keep the first, skip the rest and log a warning naming both sources. Keep the first by a **deterministic** order (the catalog's sorted order), so which copy wins never varies between turns.
  - Pass `*args, **kwargs` through in `FilteredMCPClient.list_tools_sync` so Strands' cursor is honoured, with a 20-page cap matching `MAX_CAPABILITY_PAGES`.
  - Drop and log any tool name over 64 characters.
  - Tests: two clients sharing a name (agent builds, one copy kept, warning logged); two records with one URL (one client); a two-page client; a repeating-cursor client.
- **Subtracts**: yes. The override that swallows its own arguments goes, and so does a class of whole-agent failures.
- **Unlocks**: the unreleased account MCP server's platform `whoami` can ship without clashing with Canvas and Salesforce.
- **Effort**: Low
- **Impact**: High
- **Evidence**: **measured.** 5 failed prod scheduled runs on 10-09, with the Strands error in the ScheduledRuns worker logs (#1527). The pagination half is verified on disk and latent.
- **Ship means**: one backend PR this week. A rename of `whoami` in the server repo is optional and not a substitute.
- **Decline means**: users with both clashing servers keep failing every schedule built on the default snapshot. The workaround is editing each schedule's tool list.
- **Recommendation**: **Ship, first.** It is the only measured prod failure on the board. ⚠️ Prompt-cache contract: the surviving tool set must be identical every turn, so dedupe on sorted order, never on load completion order (parallel pre-flight, #1406, makes completion order non-deterministic).
