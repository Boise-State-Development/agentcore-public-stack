### 1. Correct the cache-write premium and fix the Global/Regional rate tier

- **Source**: research/2026-08-28.md ▸ Top 5 #1 | review-queue.md (open since 2026-08-28)
- **Surface area**: docs / frontend / backend — `CLAUDE.md` (the `$2.50/MTok` figure appears **twice**: the prompt-cache contract and the cost-effectiveness tenet), `frontend/ai.client/src/app/admin/manage-models/models/curated-models.ts:135` (every Claude template's four rate fields), the managed-models DynamoDB rows in dev and prod, and the read path at `apis/shared/costs/pricing_config.py:75`
- **Change**: three steps, ascending in cost. (1) Replace the flat `$2.50/MTok` in CLAUDE.md with the actual rule — **cache write = 1.25× base input** (2× at 1h TTL, read 0.1×) — and note that `us.*` CRIS prices **10% above** `global.*`. A flat figure was always going to be wrong once we ran more than one model. (2) Reconcile the curated table to the **Regional** tier, or better, make the tier explicit so the mismatch can't recur silently — our default model `us.anthropic.claude-haiku-4-5-20251001-v1:0` is declared with Global numbers ($1.00/$1.25/$0.10/$5.00) against Regional actuals ($1.10/$1.375/$0.11/$5.50). (3) Query the managed-models table in dev to see what admins actually seeded.
- **Subtracts**: yes — a wrong constant that **gates merges** on the model call path, plus (on the explicit-tier route) a hand-maintained duplicate of AWS's own price list.
- **Unlocks**: cost numbers that are actually right — the precondition for every other cost decision in the roadmap, Proposal #6's measurement included — and a possible **~9% cut on all model spend** if `global.*` profiles are permissible (they price 9.1% below CRIS across all four fields, and we already run one, so the mechanism is proven).
- **Effort**: Low · **Impact**: High
- **POC findings**: not POCed.
- **Ship means**: one PR fixing the doc and the table, plus one dev query. ⚠️ **Do NOT retroactively rewrite historical cost rows** — fix forward and annotate, or the time series the whole cost-effectiveness arc depends on loses comparability. The `global.*` question is a separate decision needing a data-residency review nobody has done; don't bundle it.
- **Decline means**: `wastedUsd`, `partialMissUsd`, per-session cost and the admin cost anatomy keep under-reporting our default model by a flat 10%, and the contract's headline number stays wrong by −65% to +82% depending on which model you were reasoning about.
- **Recommendation**: **Ship** — cheapest item on the board and upstream of everything else we measure. The doc fix alone is minutes.

### 2. Make `supported_params` omission mean *unsupported*, and audit model lifecycle

- **Source**: research/2026-08-28.md ▸ Top 5 #3 | review-queue.md (open since 2026-08-28) | Friction ≥2
- **Surface area**: backend / frontend — `apis/inference_api/chat/routes.py:294–360` (the merge/filter and its pass-through loop), `agents/main_agent/core/model_config.py:45–102` (`_BEDROCK_PARAM_MAP` / `KNOWN_CANONICAL_PARAMS`), `curated-models.ts` (Opus 4.7 + Sonnet 5 templates), `apis/shared/models/models.py` (`SupportedParams`)

- **Subtracts**: yes — one default inversion closes the **entire class**, instead of adding `temperature: {supported: false}` to every 4.7+ template and hoping nobody forgets one on the next model.
- **Unlocks**: safe Opus 5 onboarding (it inherits the same restriction), and the first model-lifecycle signal the registry has ever had.
- **Effort**: Low · **Impact**: High
- **POC findings**: not POCed.
- **Ship means**: one backend PR for the inversion + drop-log, one short audit note for the Bedrock dates. Scope the inversion to spec-declaring records and ship the log in the same PR — that's the mitigation for dropping a param someone relied on.
- **Decline means**: any path that supplies a temperature for those models — a legacy client, an agent binding, an admin adding `temperature` to `supportedParams`, or a hand-created record with no spec — **hard-fails mid-stream**, and the exposure grows the moment Opus 5 lands.

### 7. Port the reference repo's context-overflow hardening
