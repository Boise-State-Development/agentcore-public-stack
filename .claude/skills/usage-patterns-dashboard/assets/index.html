Usage patterns

Spend by pattern

Each conversation gets the first pattern whose rule it matches. The lever is the engineering change that would make that pattern cheaper without cutting answer quality.

What each pattern pays for

Spend split by cost mechanism. Idle re-writes are cache writes after a pause of 5 minutes or more.

Where the money goes

All conversations in the window, by mechanism.

Daily spend by pattern

The costliest patterns; the rest are grouped as Other.

Modifiers

Traits that cut across patterns. A conversation can carry several, so shares add up to more than 100%.

Conversations

The 30 costliest conversations in the window. Spend is within the window; lifetime includes earlier months. Session ids open the admin drill-down.

Diagnostics

The 5-minute cliff

Cache-write spend by the pause before each call. Labels show how often a call re-wrote more than it read.

Tool reliability

Tools with 20+ calls. Follow-up spend is the cost of the model call that handled the error, split across the tools that failed in that batch.

Models

Write:read is cache-write tokens per cache-read token; a healthy conversation reads far more than it writes. Calls with no cost are unpriced (a model without a catalog row).

Attachments

Conversations by what was uploaded into them (API pipelines excluded).

Context management

Compaction and trimming events recorded on calls in the window, and the spend of the conversations they happened in. Unreachable floor means compaction could not get the context under its target because the protected recent turns alone were too big.

Cost mechanisms

First write
The cache write on a conversation's first call.
Idle re-write
Cache writes on calls after a pause of 5 minutes or more, when the cached context had expired.
Live re-write
Partial misses inside the cache window: history re-written while still warm.
Growth write
Caching genuinely new content inside the cache window.
Cache read
Reading the cached context on every call.
Output
